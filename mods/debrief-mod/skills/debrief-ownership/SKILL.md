# 코드 턴의 마무리 브리핑

debrief의 핵심 계약은 "무엇이 바뀌었는지 + 다음 행동 하나"를 두 문장으로 말하는 것이다. 코드를 다룬 턴에서는 다음 행동을 사용자가 **직접 확인할 핵심**으로 고른다. 에이전트가 쓴 코드를 사용자가 읽지 않고 넘어가는 인지 부채를 줄이려는 장치다.

## 다음 행동을 고르는 기준

아래 중 가장 위험한 것 하나만 말한다. 위에서부터 고른다.

1. **삭제·되돌릴 수 없는 일.** 파일·데이터 삭제, `rm`, `git reset`, `git push`, 마이그레이션.
2. **보안·데이터 경로.** 인증, 권한, 시크릿, `.env`, 외부로 나가는 요청, 저장 위치.
3. **동작 변경.** 같은 입력에 결과가 달라지는 곳, 기본값, 공개 인터페이스.
4. **에이전트의 가정.** 확인하지 못하고 그렇다고 친 것(파일 위치, 필드 이름, 환경).
5. **확인·되돌리기 방법.** 위에 해당하는 게 없을 때, 어떻게 검증하고 어떻게 되돌릴지.

고른 하나를 "무엇을 어떻게 보면 되는지"까지 구체적으로 말한다. "확인해 주세요"만 쓰지 않는다.

## 문구 만들기

- 두 문장, 사용자 언어. 첫 문장은 바뀐 점, 둘째는 다음 행동이다.
- 파일 목록, 체크리스트, 코드, JSON, HTML 주석을 넣지 않는다.
- 숫자·경로는 소리로 들어서 알아듣는 것만 쓴다. 긴 해시나 경로 대신 "설정 파일", "테스트 세 건"처럼 말한다.
- 통과한 테스트와 못 돌린 검증을 구분한다. 돌리지 못한 것은 사실대로 말한다.

| 나쁨 | 좋음 |
| --- | --- |
| 작업을 완료했습니다. 확인 부탁드립니다. | 훅 재시도 로직을 바꿨고 테스트 세 건이 통과했습니다. 재시도가 세 번으로 고정된 점이 맞는지 직접 봐 주세요. |
| 파일 다섯 개를 수정했습니다. 리뷰해 주세요. | 설정 저장을 임시 파일로 쓰고 교체하게 바꿨습니다. 저장 도중 끊겼을 때 기존 파일이 남는지 한 번 시험해 보세요. |

## 호출 규칙

- 사용자에게 보이는 턴 끝에 **한 번만** 부른다(0–1회). 새 사실도 다음 행동도 없으면 부르지 않는다.
- 필수 인자는 `text`, `voice`, `speed`, `volume`이다. 훅이 알려 준 세션 아이디와 목소리를 그대로 쓴다. 계약상 `text`는 800자 이하이고 두 문장이 기준이다.
- 서브에이전트는 사용자를 브리핑하지 않는다. 일이 끝나면 `priority: "subagent"`, `lane: "work"`로 사실 한 줄만 말한다.
- 사소한 변경(오타, 주석, 포맷)은 다음 행동을 억지로 만들지 않는다.

## debrief-mod의 speak 가드

debrief-mod가 켜져 있으면 아래에 걸린 호출이 거부된다. 거부 문구가 도구 오류로 돌아온다.

| 거부 | 고치는 법 |
| --- | --- |
| 한 턴에 두 번째 호출 | 이미 한 번 말했다. 다시 부르지 않는다 |
| 240자 초과 | 두 문장으로 줄여 다시 한 번 |
| 3문장 초과 | 다음 행동 하나만 남긴다 |
| 목록 형태(`-`, `1.`로 시작하는 줄) | 문장으로 풀어 쓴다 |

가드는 `priority: "subagent"`를 검사하지 않는다. 거부는 실패가 아니라 문구를 다듬으라는 신호다.
