# decide 질문 묶음

모두 `decide_many` 한 번으로 보낸다. state는 사실만 담고, 판단은 질문에 둔다. 각 질문은 위 `SKILL.md`의 규칙대로 직접 묻는 한 문장이다.

| 상황 | state에 넣는 것 | 질문(type) |
| --- | --- | --- |
| 이슈, 문의 분류 | 제목, 본문, 재현 조건, 영향 범위 | 긴급한가(noul), 어느 팀인가(choice), 사용자 영향의 크기는(score 낮음/보통/높음) |
| 변경의 위험 | diff 요약, 건드린 모듈, 테스트 결과 | 되돌리기 어려운 변경인가(noul), 리뷰가 더 필요한가(noul), 위험 수준은(score 낮음/보통/높음) |
| 에러 로그 분류 | 에러 메시지, 스택 상단, 최근 변경 | 원인 영역은(choice: 코드, 설정, 의존성, 인프라, 데이터), 재현 가능해 보이는가(noul) |
| 테스트 실패 | 실패 테스트 이름, 메시지, 최근 변경 파일 | 실패가 이번 변경 때문인가(noul), 불안정(flaky) 테스트인가(noul) |
| 작업 완료 확인 | 요청 원문, 한 일 요약, 실행한 검증 | 요청이 모두 충족됐는가(noul), 검증이 충분한가(noul) |
| 의견 갈림 정리 | 두 안의 내용과 근거 | 어느 안이 요구에 맞는가(choice: 안 이름), 확신하기에 정보가 충분한가(noul) |

쓰는 요령.

- state가 길면 판단에 필요한 사실만 남긴다. 서버는 같은 state를 캐시하므로 같은 state로 질문을 늘려 다시 보내도 싸다.
- 결과로 사람에게 영향이 가는 행동(삭제, 배포, 거절)을 정하지 않는다. 판단은 참고이고 최종 결정은 사용자가 한다.
- 임계값을 정하기 전에 같은 질문을 실제 사례 몇십 개에 돌려 본다. 백엔드를 바꾸면 다시 잰다.
